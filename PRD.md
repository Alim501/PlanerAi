## 1. Цель проекта

Веб-приложение для студентов, которое помогает планировать подготовку к экзаменам, управлять конспектами и использовать искусственный интеллект для автоматизации учёбы.

### Ключевые ценности

| Пользователь | Ценность |
|---|---|
| Студент | Персональный учебный план на основе своих конспектов, без ручного составления |
| Преподаватель / куратор | База структурированных конспектов с ключевыми понятиями |
| Администратор | Управление пользователями, контентом и предметами |

---

## 2. Роли пользователей

### 2.1 Student (базовая роль при регистрации)

**Может:**
- Регистрироваться и авторизовываться
- Создавать, редактировать и просматривать свои планы
- Загружать и просматривать конспекты
- Оценивать чужие конспекты (1–5 звёзд)
- Запускать AI-генерацию планов и AI-анализ своих конспектов
- Управлять своим профилем

**Не может:**
- Удалять чужие конспекты и планы
- Управлять пользователями и предметами

### 2.2 Moderator

Все права Student, плюс:
- Видит все конспекты и файлы
- Добавляет ключевые слова к любым конспектам вручную
- Создаёт и редактирует предметы (subjects)
- Удаляет планы любых пользователей

### 2.3 Admin

Все права Moderator, плюс:
- Просматривает список всех пользователей
- Обновляет профиль любого пользователя
- Назначает и снимает роли
- Удаляет предметы

## 3. User Stories

---

### US-01 — Регистрация и вход

**Как** новый пользователь,
**я хочу** зарегистрироваться по email и паролю и войти в систему,
**чтобы** получить доступ к своим планам и конспектам.

**Критерии приёмки:**
- При регистрации система проверяет уникальность email
- После входа выдаётся JWT (HttpOnly cookie); пользователь не видит токен напрямую
- При закрытии вкладки и повторном открытии сессия восстанавливается через refresh token
- Кнопка «Выйти» завершает сессию и удаляет cookie

---

### US-02 — Загрузка и анализ конспекта

**Как** студент,
**я хочу** загрузить файл конспекта (PDF, DOCX или фото) и запустить AI-анализ,
**чтобы** автоматически получить краткое содержание, ключевые понятия и уровень сложности.

**Критерии приёмки:**
- Поддерживаются форматы: PDF, DOCX, JPG, PNG, TXT (до 10 MB)
- После загрузки конспект отображается в каталоге с именем и предметом
- Кнопка «Анализировать» запускает AI; после завершения поле summary и keywords заполнены
- Ключевые слова отображаются в виде тегов на карточке конспекта
- Если анализ ещё не проводился — поля summary и keywords пусты

---

### US-03 — AI-генерация учебного плана

**Как** студент,
**я хочу** указать предмет, длительность и темы и получить готовый учебный план,
**чтобы** не тратить время на ручное составление расписания.

**Критерии приёмки:**
- Форма содержит поля: предмет, количество недель, уровень сложности, темы, цели
- После отправки система автоматически находит конспекты пользователя, подходящие по темам
- Готовый план отображается с разбивкой по неделям и задачами
- Каждая задача содержит ссылки на конспекты из базы (если найдены) или внешние ресурсы
- Генерация занимает не более 30 секунд; в процессе показывается индикатор загрузки

---

### US-04 — Просмотр плана и ресурсов задачи

**Как** студент,
**я хочу** открыть план и видеть по каждой задаче прикреплённые конспекты и внешние ресурсы,
**чтобы** сразу переходить к нужным материалам без поиска.

**Критерии приёмки:**
- На странице плана отображаются недели в порядке возрастания номера
- Каждая задача раскрывается и показывает список `relatedNotes` (название конспекта, кликабельная ссылка) и `externalResources` (текст/ссылка)
- Если ресурсов нет — блок ресурсов скрыт или отображается заглушка «Нет прикреплённых материалов»
- Клик по конспекту открывает страницу конспекта

---

### US-05 — Поиск конспектов по ключевым словам

**Как** студент,
**я хочу** найти конспекты по нескольким ключевым словам,
**чтобы** быстро получить все материалы по нужной теме.

**Критерии приёмки:**
- Поле поиска принимает одно или несколько слов через запятую или пробел
- Результат возвращает конспекты, у которых совпадает хотя бы одно ключевое слово
- Поиск нечувствителен к регистру
- Если совпадений нет — отображается сообщение «Конспекты не найдены»
- Результаты можно дополнительно фильтровать по предмету

---

### US-06 — Оценка конспекта

**Как** студент,
**я хочу** оценить чужой конспект от 1 до 5 звёзд,
**чтобы** помочь другим пользователям найти наиболее качественные материалы.

**Критерии приёмки:**
- На странице конспекта отображается компонент звёздного рейтинга
- Пользователь может поставить или изменить свою оценку
- После голосования средний рейтинг и число оценок обновляются
- Своя текущая оценка визуально выделена
- Нельзя оценить собственный конспект более одного раза (повторный запрос обновляет оценку)

---

### US-07 — Управление предметами (Moderator/Admin)

**Как** модератор,
**я хочу** создавать, редактировать и удалять предметы,
**чтобы** поддерживать актуальный справочник для классификации планов и конспектов.

**Критерии приёмки:**
- Раздел «Предметы» доступен в админ-панели только для ролей Moderator и Admin
- Создание предмета: поле «Название», кнопка «Сохранить»; после сохранения предмет сразу появляется в списках
- Редактирование — инлайн или через форму
- Удаление доступно только Admin; перед удалением показывается предупреждение
- Предмет нельзя удалить пока он используется в планах или конспектах (ошибка с объяснением)

---

### US-08 — Управление пользователями (Admin)

**Как** администратор,
**я хочу** просматривать всех пользователей, менять их роли и данные,
**чтобы** контролировать доступ к системе.

**Критерии приёмки:**
- Таблица пользователей отображает: ID, имя, email, роли
- Для каждого пользователя доступны действия: изменить имя, изменить пароль, добавить/снять роль
- Изменения применяются немедленно; пользователь узнает о новых правах при следующем запросе
- Администратор не может снять роль ADMIN у самого себя
- Список пользователей доступен только с ролью ADMIN

---

### US-09 — Улучшение задачи через AI

**Как** студент,
**я хочу** улучшить формулировку задачи с помощью AI,
**чтобы** сделать её более конкретной и понятной.

**Критерии приёмки:**
- На странице задачи (или при создании) есть кнопка «Улучшить с AI»
- AI возвращает: улучшенное название, развёрнутое описание, конкретные рекомендации и оценку времени
- Пользователь может принять предложенный вариант или отклонить его
- Принятие заменяет текущие поля задачи; исходный вариант можно отменить через форму
- В процессе обращения к AI показывается спиннер

---

### US-10 — Ручное создание и редактирование плана

**Как** студент,
**я хочу** вручную создать план с произвольными неделями и задачами,
**чтобы** иметь полный контроль над расписанием подготовки без участия AI.

**Критерии приёмки:**
- Форма создания плана позволяет указать название, описание, предмет, сложность, даты начала и окончания
- Можно добавить любое количество недель; в каждую неделю — любое количество задач
- После сохранения план появляется в списке «Мои планы»
- Редактирование плана позволяет изменить мета-данные (название, предмет и т.д.)
- Добавление и удаление задач доступно отдельно через раздел задач

## 5. Модель данных

### Основные сущности и связи

```
User ──────────────────────────────────────────────────────────
  id, email, password, firstName, lastName, roles[]

  User ─(ManyToMany через UserPlanProgress)─► Plan
  User ─(OneToMany)─────────────────────────► Note

UserPlanProgress ──────────────────────────────────────────────
  user, studyPlan, startDate, endDate, progress (0.0–1.0)

Plan ──────────────────────────────────────────────────────────
  id, title, description, difficulty, subject
  Plan ─(OneToMany)─► Week

Week (plan_week) ──────────────────────────────────────────────
  id, weekNumber, title, estimatedHours, plan
  Week ─(OneToMany)─► Task

Task ──────────────────────────────────────────────────────────
  id, title, description, taskStatus (PENDING/...), createdAt
  Task ─(ManyToMany via tasks_notes)──────────────► Note[]
  Task ─(ElementCollection via task_external_resources)─► String[]
                                                   (внешние ресурсы)

Note ──────────────────────────────────────────────────────────
  id, title, fileUrl (S3), format (PDF/DOCX/JPG/PNG/TXT)
  summary, difficulty, language
  viewCount, averageRating, ratingCount
  subject, user, createdAt
  Note ─(ManyToMany via note_keywords)────────────► Keyword[]
  Note ─(OneToMany)───────────────────────────────► NoteRating[]

Keyword ───────────────────────────────────────────────────────
  id, word (уникальное, case-insensitive)

Subject ───────────────────────────────────────────────────────
  id, name
```

### Таблицы связей

| Таблица | Описание |
|---|---|
| `user_plan_progress` | Пользователь ↔ план (с прогрессом) |
| `tasks_notes` | Задача ↔ конспект (внутренние ресурсы) |
| `task_external_resources` | Внешние ресурсы задачи (строки) |
| `note_keywords` | Конспект ↔ ключевое слово |

## 6. Функциональные требования

### 5.1 Аутентификация и профиль

#### Регистрация / Вход

- Регистрация по email + пароль
- Вход с выдачей JWT в HttpOnly cookie (access + refresh token)
- Проверка статуса сессии при загрузке приложения
- Выход из системы (logout)
- Авто-обновление access token через refresh token

#### Профиль пользователя

- Просмотр данных (имя, фамилия, email, роли)
- Изменение имени и фамилии
- Смена пароля (требуется старый пароль)

---

### 5.2 Предметы (Subjects)

Предметы — это теги/категории для планов и конспектов.

| Действие | Кто может |
|---|---|
| Просмотр всех предметов | Все авторизованные |
| Создание предмета | Admin, Moderator |
| Редактирование предмета | Admin, Moderator |
| Удаление предмета | Admin |

---

### 5.3 Планы обучения

#### Создание плана вручную

Пользователь создаёт план через форму:
- Название, описание, сложность
- Предмет (из справочника)
- Дата начала и окончания
- Недели с задачами (задаются вручную)

**Запрос:** `POST /api/plans`

```json
{
  "title": "Подготовка к экзамену по Java",
  "description": "...",
  "difficulty": "intermediate",
  "subjectId": 2,
  "startDate": "2025-10-15",
  "endDate": "2025-12-15",
  "weeks": [
    {
      "weekNumber": 1,
      "title": "Основы Java",
      "estimatedHours": 8,
      "tasks": [
        { "title": "Изучить типы данных", "description": "..." }
      ]
    }
  ]
}
```

#### Создание плана через AI

Пользователь заполняет краткую форму — система автоматически:
1. Находит подходящие конспекты пользователя по темам
2. Передаёт конспекты как контекст в Gemini
3. AI генерирует полный план с задачами и ресурсами
4. Каждая задача получает ссылки на конспекты из базы и/или внешние ресурсы
5. Сохраняет готовый план в БД

**Запрос:** `POST /api/ai/plans/generate`

```json
{
  "subject": "Математический анализ",
  "durationWeeks": 8,
  "level": "intermediate",
  "topics": ["производные", "интегралы", "пределы"],
  "goals": "Подготовиться к экзамену",
  "subjectId": 3
}
```

| Поле | Обязательное | Описание |
|---|:---:|---|
| `subject` | ✅ | Название предмета |
| `durationWeeks` | ✅ | Количество недель (1–52) |
| `level` | ❌ | `beginner` / `intermediate` / `advanced` |
| `topics` | ❌ | Темы — по ним ищутся конспекты |
| `goals` | ❌ | Цели обучения |
| `subjectId` | ❌ | ID предмета для дополнительной фильтрации конспектов |

#### Просмотр и управление планами

- Список своих планов с фильтрацией по предмету и статусу
- Поиск по названию плана
- Просмотр плана: недели → задачи → прикреплённые конспекты и внешние ресурсы
- Редактирование плана (название, описание, сложность, предмет)
- Удаление плана (только Admin/Moderator)

---

### 5.4 Задачи (Tasks)

Задачи вложены в недели плана.

- Добавление задачи в неделю
- Просмотр задач по неделе или по всему плану
- Редактирование задачи
- Удаление задачи

У каждой задачи есть:
- `taskStatus`: `PENDING` (начальный статус)
- `relatedNotes[]`: конспекты из базы (линкуются при AI-генерации или вручную)
- `externalResources[]`: внешние ресурсы (строки — книги, ссылки)

#### Улучшение задачи через AI

`POST /api/ai/tasks/improve`

```json
{
  "taskTitle": "Изучить ООП",
  "taskDescription": "...",
  "subject": "Java"
}
```

Возвращает улучшенное название, описание, предложения и оценку времени.

---

### 5.5 Конспекты (Notes)

#### Загрузка конспекта

Загрузка файла через multipart/form-data.

- Поддерживаемые форматы: **PDF, DOCX, JPG, PNG, TXT**
- Максимальный размер: 10 MB
- Файл сохраняется в AWS S3
- Метаданные (название, предмет, формат, пользователь) — в PostgreSQL

**Эндпоинт:** `POST /api/notes/upload`
Параметры формы: `file`, `title`, `subjectId`

#### Просмотр и поиск конспектов

- Все конспекты с фильтрацией:
  - По предмету
  - По ключевым словам (`GET /api/notes/byKeywords?keywords=математика,анализ`)
  - Сортировка по дате и популярности
- Просмотр детальной страницы конспекта
- Скачивание файла
- Увеличение счётчика просмотров (`POST /api/notes/{id}/view`)

#### Оценивание конспектов

- Пользователь ставит оценку 1–5 звёзд
- Отображается средний рейтинг и число оценок
- Пользователь может посмотреть свою оценку

#### Ключевые слова

- Ключевые слова уникальны и хранятся в нижнем регистре (case-insensitive)
- При повторном добавлении существующее слово переиспользуется
- Admin/Moderator может добавить слова вручную: `POST /api/notes/{id}/keywords`
- AI автоматически добавляет слова при анализе конспекта
- Поиск по ключевым словам возвращает конспекты, у которых совпадает хотя бы одно слово

---

### 5.6 Администрирование

`GET /api/admin/users` — список всех пользователей
`GET /api/admin/users/{id}` — данные пользователя
`PUT /api/admin/users/{id}/update-profile` — изменение имени/фамилии
`PUT /api/admin/users/{id}/change-password` — смена пароля
`POST /api/admin/users/{id}/role/{roleName}` — добавить роль
`DELETE /api/admin/users/{id}/role/{roleName}` — снять роль

Доступно только пользователям с ролью **ADMIN**.

## 7. AI-функциональность

### 6.1 Анализ конспекта

**Эндпоинт:** `POST /api/ai/notes/analyze`
**Тело:** `{ "noteId": 5 }`

**Что происходит:**
1. Backend получает presigned URL файла из S3
2. Отправляет URL в AI-Service
3. Gemini нативно анализирует документ (PDF/DOCX/изображение через OCR)
4. AI-Service возвращает:

```json
{
  "summary": "Краткое содержание (≤250 символов)",
  "key_concepts": ["производная", "дифференциал", "предел", "..."],
  "difficulty": "intermediate",
  "language": "ru",
  "word_count": 1250
}
```

5. Данные сохраняются в Note: `summary`, `difficulty`, `language`
6. Ключевые слова добавляются в таблицу `Keyword` и линкуются к конспекту

> ⚠️ **Важно:** для участия конспекта в авто-подборе при генерации плана необходимо сначала провести AI-анализ.

### 6.2 Генерация плана с привязкой конспектов

**Алгоритм авто-подбора конспектов:**

```
topics пользователя → нормализация (lowercase, split по пробелам, слова > 2 символов)
       ↓
findByUserIdAndKeywordsIn(userId, keywords) — поиск конспектов по ключевым словам
       ↓
Скоринг:
  +3 за каждое совпавшее ключевое слово
  +2 если конспект относится к указанному subjectId
       ↓
Топ-10 конспектов → передаются в Gemini как контекст
```

**Что Gemini получает о каждом конспекте:**
```
[id=5] "Лекция 1: Производные" (уровень: intermediate, ключевые слова: производная, дифференциал, предел)
       | Краткое содержание: "Определение производной и правила дифференцирования..."
```

**Что Gemini возвращает для каждой задачи:**
```json
{
  "title": "Изучить определение предела",
  "description": "Работа с конспектом лекции",
  "internal_note_ids": [5, 8],
  "external_resources": []
}
```

**Правило:** `internal_note_ids` содержит только ID из переданного списка. Если подходящих конспектов нет — `external_resources` содержит книги/ссылки.

### 6.3 Улучшение задачи

**Эндпоинт:** `POST /api/ai/tasks/improve`

Gemini улучшает формулировку задачи и возвращает:
- `improvedTitle` — улучшенное название
- `improvedDescription` — детальное описание
- `suggestions` — конкретные рекомендации
- `estimatedTime` — оценка времени выполнения
- `difficulty` — уровень сложности задачи

## 9. Нефункциональные требования

### Безопасность
- Пароли хранятся в хэшированном виде (BCrypt)
- JWT в HttpOnly cookie — недоступны из JavaScript
- Access token + Refresh token (разные сроки жизни, настраиваются через `.env`)
- Role-based access control (STUDENT / MODERATOR / ADMIN)
- Пресайнд URLs для S3 — прямой доступ к файлам без публичных бакетов

### Файлы и хранилище
- Файлы конспектов хранятся в AWS S3 (не в БД)
- Максимальный размер файла: **10 MB**
- Поддерживаемые форматы: PDF, DOCX, JPG, PNG, TXT
- Генерация presigned URL для скачивания (время жизни URL ограничено)

### Производительность
- Авто-подбор конспектов при AI-генерации: один SQL-запрос на все note IDs (без N+1)
- Кешированные поля в Note: `averageRating`, `ratingCount` — не пересчитываются при каждом запросе

### База данных
- Схема управляется через Flyway (миграции `V1...Vn__*.sql`)
- `ddl-auto=none` — Hibernate не трогает схему самостоятельно
- При падении миграции: `flyway.repair()` автоматически очищает failed-запись перед повторным запуском

### Масштабируемость
- AI-модель и параметры настраиваются через `.env` (`GEMINI_MODEL`, `GEMINI_API_KEY`)
- Новые AI-модули добавляются в AI-Service независимо от Backend

## Запуск проекта локально

### Порядок запуска

```
PostgreSQL → AI-Service → Spring Boot Backend → Angular Frontend
```

### 1. База данных

```sql
CREATE DATABASE task_service;
```

### 2. AI-Service

```bash
cd AI-Service
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
# Создать .env: GEMINI_API_KEY=... GEMINI_MODEL=gemini-2.5-flash
python -m app.main
```

### 3. Backend

```bash
cd Back
# Создать .env: DB_URL, DB_USERNAME, DB_PASSWORD, JWT_SECRET, AWS_*, AI_SERVICE_URL
./mvnw spring-boot:run
```

### 4. Frontend

```bash
cd Front
npm install
npm run start
```

### Переменные окружения

**Back/.env:**
```
DB_URL=jdbc:postgresql://localhost:5432/task_service
DB_USERNAME=...
DB_PASSWORD=...
JWT_SECRET=...
ACCESS_TOKEN_EXP=...
REFRESH_TOKEN_EXP=...
AWS_ACCESS_KEY_ID=...
AWS_SECRET_ACCESS_KEY=...
AI_SERVICE_URL=http://localhost:8000
FRONT_URL=http://localhost:4200
```

**AI-Service/.env:**
```
GEMINI_API_KEY=...
GEMINI_MODEL=gemini-2.5-flash
```

### Troubleshooting

**`ng: command not found`** при запуске фронта:
```bash
cd Front && npm install && npm run start
```

**Ошибка Flyway при старте:**
```sql
DELETE FROM flyway_schema_history WHERE version = 'N' AND success = false;
```
Или просто перезапустить — `flyway.repair()` срабатывает автоматически.

**AI Service не отвечает:**
```bash
curl http://localhost:8000/health
# Проверить GEMINI_API_KEY в AI-Service/.env
```
